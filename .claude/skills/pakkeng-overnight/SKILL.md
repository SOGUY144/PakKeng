# งานคืนนี้ของ PakKeng — ทั้งเว็บแอปและทั้งสี่เกม

รับช่วง checkout ปัจจุบันของ nasal-trainer-web ทำตั้งแต่เลือกกิจกรรม เช็กอุปกรณ์ เล่นทั้งสี่เกม จบรอบ กลับมาฝึก และผู้ดูแลดูผล ทบทวนทุก route ที่พบเพิ่มด้วย ลงมือแก้จริงและทดสอบทันที ตัดสินใจเรื่องกราฟิก กล้อง จังหวะ และลำดับงานเองได้ บึงเรียกเพื่อนเป็นหนึ่งในสี่เกม รายละเอียดด่านกบด้านล่างเป็นส่วนหนึ่งของเกณฑ์ส่งมอบ

## รูปแบบการเล่นที่เด็กแยกออกจากกันได้

ใช้ UI ภาษาไทยและบุคลิกภาพเดิมของเกมเป็นฐาน ปรับประสบการณ์ผ่านสิ่งที่เด็กได้เลือก สิ่งที่ทำ และผลที่เกิดในฉาก ให้แต่ละเกมมีลำดับการเล่นต่างกันจริง ใช้ตัวจัดการสัญญาณ/แผนฝึกเดิม ตรวจความหมายของเหตุการณ์จริงก่อนผูกแอนิเมชัน

| เกม | สิ่งที่เด็กเลือกและทำ | ผลในฉากและเงื่อนไขจบรอบ |
|---|---|---|
| กบข้ามบึง | เลือกว่าอยากไปหาเพื่อนตัวไหนก่อน แล้วฟังและเรียกชื่อ | เมื่อจับเสียงที่ใช้ได้ เพื่อนหันมา กบกระโดดไปหา เด็กเลือกเพื่อนถัดไปและเห็นกลุ่มเพื่อนเมื่อจบ |
| บอลลูน | เลือกบอลลูนหรือจุดหมาย ลองประคองการออกเสียงตามช่วงที่แผนเดิมกำหนดและพักระหว่างลูก | เห็นความต่อเนื่องผ่านการลอยขึ้นของบอลลูน ถึงหมุดแล้วได้ส่งลูกถัดไป ไม่มีแรงจูงใจให้ตะโกนหรือฝืนลากเสียง |
| วิ่ง | เลือกทางแยกบนแผนที่ แล้วใช้คำตามลำดับแผนเพื่อเคลื่อนทีละช่วง | เห็นจุดแวะและปลายทางของเส้นที่เลือก จบตามจำนวนช่วงในรอบ รองรับการไปด่านประตูเมื่อแผนเปิดไว้ |
| ประตู | เลือกลายกุญแจหรือบานที่จะเปิด ฟังคำและลองเสียงเป้าหมายที่ผู้เชี่ยวชาญตั้ง | ใช้เหตุการณ์เปิดจากตรรกะเดิมให้สลักเคลื่อนและเผยสิ่งที่อยู่ข้างหลัง เด็กเห็นปลายทางของตนเอง มีทางลองซ้ำ/พัก |

หน้าแรกให้เห็นว่าแต่ละเกมชวนทำอะไร เช่น “เรียกเพื่อน”, “พาบอลลูนไปส่ง”, “เลือกทางวิ่ง”, “เปิดประตู” ผ่านชื่อ ภาพ และกริยาสั้นตามบริบท ให้เด็กเลือกในกรอบแผนของผู้ดูแล มีทางเล่นต่อจากรอบเดิมเมื่อข้อมูลรองรับ หน้าเตรียมอุปกรณ์ใช้คำบอกขั้นต่อไปทีละเรื่อง หน้าผลเด็กเน้นเหตุการณ์ที่เพิ่งทำสำเร็จ ส่วน dashboard ผู้ดูแลแสดงรายละเอียดที่ใช้ตัดสินใจได้ ใช้ปุ่มพัก ย้อนกลับ และฟังซ้ำอย่างสม่ำเสมอ แต่เลือกตำแหน่งและจำนวนองค์ประกอบตามงานของแต่ละหน้า ตัดแถวการ์ด ป้าย คำซ้ำ และขั้นกดยืนยันที่ไม่ช่วยให้เด็กตัดสินใจ

## ปรับตามพื้นที่หน้าจอและวิธีป้อนข้อมูล

ตรวจ `src/styles/kid.css` โดยเฉพาะ `.kid-frame`, `--kid-col` และ desktop grid ที่ให้พื้นที่ข้างฉากแก่เครื่องมือเดโม บันทึกภาพก่อนแก้และเลือกจุดเปลี่ยนจากพื้นที่ที่เนื้อหาต้องใช้ ใช้ CSS/container queries ตามความเหมาะสม รองรับ touch, mouse และ keyboard โดยใช้ state เกมชุดเดียว

- **มือถือ 390×844** จัดฉากกับคำปัจจุบันให้อยู่ในสายตาพร้อมกัน วางการกระทำหลักในระยะนิ้วโป้ง ปุ่มรองเปิดได้โดยไม่บังเป้าหมาย คำนึงถึง safe area และความสูงจริงเมื่อแถบเบราว์เซอร์แสดง
- **iPad 820×1180 และ 1180×820** แนวตั้งจัดพื้นที่ให้เด็กแตะเลือกได้โดยมือไม่บังตัวละคร แนวนอนให้ฉากเล่นคู่กับแถบเพื่อน/คำ/เส้นทางที่เกี่ยวข้องกับเกม ทดลองหมุนระหว่างรอบและย่อ Split View ให้แคบ ระบบต้องรักษาคำ เพื่อน คะแนน และสถานะเสียงเดิม
- **คอม 1440×900** ขยายองค์ประกอบของโลกเกมตามพื้นที่ ใช้ด้านข้างสำหรับข้อมูลหรือทางเลือกที่สัมพันธ์กับเกม มี focus ชัดและเล่นด้วยคีย์บอร์ดได้ การยืดกรอบมือถือหรือเติมพื้นที่ด้วยแผงเดโมอย่างเดียวไม่ผ่าน ย้ายเครื่องมือจำลองไปส่วนผู้ดูแลที่เปิดเมื่อจำเป็น
- ปรับกล้อง canvas และ hit target ให้สอดคล้องกับพื้นที่ฉากเมื่อ resize ตรวจว่าตัวละครและปุ่มสำคัญไม่หลุดกรอบ ภาษาไทยไม่ตัดสระ/วรรณยุกต์ และหน้าไม่มี horizontal overflow

## หลักฐานก่อนส่งมอบทั้งแอป

เล่นเกมทั้งสี่ตั้งแต่เข้า เลือก ลงมือ จนเห็นผลจริง ทดสอบทั้ง touch และ keyboard ทำตาราง route × mobile / iPad portrait / iPad landscape / desktop ระบุสถานะตามที่ทดสอบและจุดติดขัด รวม home, calibrate, result, dashboard เก็บภาพหลักของแต่ละ layout พร้อมภาพ before/after ขนาดตรงกัน เปิดดูภาพจริง ตรวจการหมุนระหว่างรอบ การกลับจากพัก และการแยก demo/device ทดสอบ 3D ทุกโลกที่รองรับและ 2D ที่เลือกได้ ถ้าใช้เพียง viewport จำลองให้ติดป้ายชัดว่าเป็น emulation และบันทึกสิ่งที่ต้องลองบน iPad จริง

ปิดงานเมื่อผ่านเกณฑ์ระดับแอปนี้รวมกับเกณฑ์ด่านกบและคำสั่งตรวจโค้ดด้านล่าง หากมีเวลาเหลือให้ไล่แก้ปัญหาที่พบระหว่างเล่นตามลำดับผลกระทบ จดจุดที่ทำจริงใน handoff หลังแต่ละช่วง

## รับช่วงให้ถูกจุด

1. อ่าน `.claude/skills/frontend-design/SKILL.md` และ `.claude/skills/cleft-speech-game/SKILL.md` รวมถึง `references/evidence-th.md` ในโฟลเดอร์สกิลหลัง ใช้หลักฐานเรื่องความหมายของสัญญาณและการฝึกเป็นข้อกำหนดของเกม
2. ตรวจ cwd, branch, git status, diff และ handoff ปัจจุบันก่อนแก้ ใช้การเปลี่ยนแปลงที่ยังไม่ commit เป็นฐานของรอบนี้ หากอีก session กำลังแก้ไฟล์เดียวกัน ให้ทำส่วนที่แยกได้ก่อน ห้าม reset งานคนอื่น เปลี่ยน remote หรือ force-push งานคืนนี้ส่งมอบในเครื่อง การ deploy, push และการเก็บเสียงเด็กอยู่นอกงาน
3. เปิดเส้นทางจริง `/#/frog` ผ่าน dev server ของ checkout นี้ อ่าน `src/screens/FrogScreen.tsx`, `src/three/gfx.ts`, `src/three/worlds/FrogWorld.tsx`, `src/logic/call.ts` และ `src/data/callWords.ts` ตามสถานะล่าสุด ตรวจหน้าบ้านและหน้าสรุปที่ต่อถึงด่าน ถ่ายภาพก่อนแก้ในขนาดเดียวกับที่จะใช้เทียบหลังแก้
4. กำหนดเส้นตายเป็น 07:00 น. ครั้งถัดไปตาม Asia/Bangkok จดเป็นวันและเวลาเต็มในบันทึกครั้งแรก ใช้เส้นตายเดิมเมื่อกลับมาทำต่อ ถ้าบริบทสั้นลงให้กลับมาอ่าน handoff ห้ามเลื่อนเส้นตายใหม่ทุกเทิร์น

## ชิ้นงานที่ต้องเล่นได้

**P0 — ทำให้บึงเป็นตัวเกม** ตอนหน้าแรกของด่านให้เด็กเห็นเพื่อนเป้าหมาย ปุ่มฟังชัด และรู้ว่ากำลังรอฟังหรือถึงตาพูด ภาพอ้างอิงมีคำ “ปู” หลายตำแหน่งและแผงหลายแผงแย่งความเด่น เช็กว่าปัญหายังอยู่แล้วรวมสิ่งที่บอกเรื่องเดียวกัน ใช้คำไทยสั้นตามจังหวะจริง ลดคำอธิบายเครื่องมือจากหน้าหลักเด็ก แต่คงป้ายเดโมที่อ่านได้และเข้าหน้าผู้ดูแลได้ บนเดสก์ท็อปจัดฉากให้ได้ใช้พื้นที่ บนมือถือให้ตัวละครและปุ่มหลักอยู่ในระยะมองเห็นและแตะสะดวก ภาพจำคือบึงของเล่นปั้นดิน ใบบัวเป็นเวที กบตัวเล็กเดินทางไปหาเพื่อน ใช้ตลิ่ง แสง เงา และสีเพื่อบอกว่าใครกำลังฟัง พักสายตาในช่วงพูด หลีกเลี่ยงการวางข้อความไทยทับวัตถุที่ขยับหรือทำข้อความเป็น texture อ่านยาก

**P0 — แสดง 3D จริงในเส้นทางปกติ** ตรวจค่า pref ที่บันทึกไว้ การรองรับ WebGL และ renderer error แยกกัน หากเป็น pref 2D ให้มีทาง “ลองฉาก 3D” ที่ค้นพบง่ายและจำตัวเลือกอย่างเคารพผู้ใช้ ใช้ Three.js และ React Three Fiber ที่มีอยู่ ต่อยอด FrogWorld กับโมเดลเพื่อน ให้เด็กเห็นท่ารอฟัง หันมาตอบ และกบกระโดดไปหาในจังหวะที่ต่างกัน ใช้กล้องที่เห็นเพื่อนเป้าหมายชัด ลดรายละเอียดก่อนลดความอ่านง่าย เมื่อ WebGL ใช้ไม่ได้ให้ 2D เล่นกิจกรรมครบและเก็บตัวเลือกเดิมได้ ทดสอบ reduced motion ด้วยท่าค้างหรือ crossfade สั้น ๆ

**P1 — ให้เด็กเลือกและมีผลต่อเกมจริง** ทำ “วันนี้อยากไปหาใครก่อน” เลือกเพื่อนจากรายการในแผนของเด็ก เช่น ปูหรือเต่า เมื่อเลือกแล้วต้องเปลี่ยนทั้งโมเดล คำตัวอย่าง ลำดับการพบ และชื่อคำในผลรอบเดียวกัน หน้าเลือกควรเรียกดูได้จากเส้นทางเด็ก มีรูปและชื่ออ่านได้ หากมีเพื่อนเดียวให้เข้ารอบเลย เมื่อจบรอบให้เห็นเพื่อนที่พบและเลือกเล่นอีกครั้งได้ เก็บผลแยกตาม id คำเดิม ตรวจกรณีเลือกต่างลำดับ ข้าม และเล่นซ้ำแล้วสถิติไม่สลับตัว ทางเลือกเชิงภาพเพิ่มเติม เช่น สีผ้าพันคอกบ ทำได้เมื่อทางเลือกหลักเล่นผ่านแล้ว

**P1 — ให้เกมตอบสิ่งที่วัดได้จริง** เสียงตัวอย่างและเสียงตอบของเกมต้องไม่นับเป็นเสียงเด็ก เหตุการณ์ได้ยินแล้วหมายถึงพบเสียงที่ใช้ได้ เด็กฟังซ้ำ พัก ข้าม หรือลองใหม่ได้ ไมค์หลุด เงียบ เสียงล้น ช่องหาย และข้อมูลค้างต้องกู้คืนได้โดยไม่ลงโทษเด็ก ห้ามสร้างเกณฑ์ “ยิ่งเสียงจมูกต่ำยิ่งชนะ” คงช่องจมูก/ปากตามสัญญาจริงและแยกผลเดโมจากอุปกรณ์ ถ้าไม่มีฮาร์ดแวร์ให้ทดสอบด้วย mock ที่ระบุแหล่งชัด บันทึกว่าส่วนทดสอบเครื่องจริงยังค้าง

## ตรวจและรับช่วงต่อ

- ทำทีละเส้นทางที่กดเล่นได้จริง จากหน้าเลือก → ฉาก → รับเสียง → จบรอบ → ผลสำหรับผู้ดูแล แก้สาเหตุเมื่อทดสอบไม่ผ่าน เปรียบเทียบกับ baseline ก่อนสรุปว่าข้อผิดพลาดเกิดจากรอบนี้
- ใช้ scripts ของ repo ได้แก่ `npm run typecheck`, `npm run lint`, `npm test` และ `npm run build` รันกับโค้ดส่งมอบ เพิ่ม regression test ที่ตรวจคำ/โมเดล/สถิติตรงกันเมื่อเปลี่ยนลำดับ และกรณีเสียงตัวอย่างหรือเฟรมเก่าทำให้ได้ยินผิด หาก tests เดิมครอบคลุมแล้วให้ใช้เดิม
- เล่นเส้นทางหลักอย่างน้อยสองขนาด เช่น 390×844 และ 1366×768 ตรวจคีย์บอร์ด โฟกัส การพักระหว่างออกเสียง และไม่ต้องเลื่อนหาปุ่มหลัก เก็บภาพก่อน/หลังที่ viewport เดียวกันอย่างน้อยหนึ่งคู่ และภาพฉาก 3D ที่โหลดโมเดลแล้วคู่กับสถานะ renderer ใน runtime หรือ draw calls รวมถึงภาพ 2D fallback แยกชื่อ เปิดดูภาพด้วยตนเอง หากเครื่องทดสอบไม่มี WebGL ให้ลอง runtime ที่มีอยู่และรองรับจริง หากยังไม่ได้ ให้ระบุว่า 3D ยังไม่ยืนยัน ห้ามแทนหลักฐานด้วย screenshot 2D
- อัปเดต `docs/OVERNIGHT_HANDOFF.md` เมื่อจบแต่ละช่วงด้วยสิ่งที่ทำแล้ว หลักฐาน ตำแหน่งไฟล์ และขั้นถัดไป ถ้าเทสต์เดิมค้างซ้ำ หลังแก้หรือเปลี่ยนวิธีอย่างมีเหตุผลสองครั้งให้บันทึก blocker แล้วเดินงานอิสระต่อ หลีกเลี่ยงเปิดโปรเซสหรือรัน page script ซ้อนซ้ำ หากงานใดต้องใช้สิทธิ์เพิ่ม ให้ข้ามไปทำงานที่อนุญาตได้
- ทำต่อโดยไม่รอผู้ใช้เลือกระหว่างทาง เมื่อรายการหลักผ่านแล้ว ให้แก้ข้อบกพร่องที่พบจากภาพจริงหรือการเล่นซ้ำภายในขอบเขตนี้ จบเมื่อส่งมอบครบหรือถึงเส้นตาย เมื่อต้องหยุดให้รายงานแยกผ่าน/ยังไม่ผ่าน/ยังไม่ได้ลอง พร้อมคำสั่งเปิดเว็บ route วิธีเลือก 3D และวิธีเล่นเส้นทางที่ตรวจแล้วให้จบในหนึ่งนาที
