# ปากเก่ง (PakKeng)

เครื่องวัดเสียงจมูกราคาถูก กับเกมฝึกพูดที่บ้าน สำหรับเด็กปากแหว่งเพดานโหว่

> **เครื่องมือฝึกเสริมที่บ้าน ภายใต้คำแนะนำของนักแก้ไขการพูด**
> ต้นแบบนี้ยังไม่ได้ตรวจสอบเทียบกับ Nasometer ใช้ดูแนวโน้มจากการฝึกเท่านั้น ไม่ใช้วินิจฉัย

- เว็บต้นแบบ: https://nasal-trainer-web.vercel.app (deploy ล่าสุด 5 พ.ย. 2569 จาก commit `5a74dac` · วิธี deploy ใหม่ดู [`HANDOFF.md`](HANDOFF.md))
- หน้าอธิบายหลักการแบบมีภาพเคลื่อนไหว: https://nasal-trainer-web.vercel.app/how-it-works.html
- ค่าทั้งหมดในเว็บตอนนี้มาจาก **สัญญาณจำลอง** (`MockSignalSource`) ยังไม่ได้ต่อ ESP32 จริง

## ที่มาของปัญหา
- เด็กปากแหว่งเพดานโหว่หลายคนยังพูดเสียงขึ้นจมูกหลังผ่าตัด เพราะประตูกั้นจมูก (velopharyngeal valve) ปิดไม่สนิท หรือติดนิสัยออกเสียงชดเชย
- การแก้ต้องฝึกพูดบ่อยกับนักแก้ไขการพูด แต่ในไทยนักแก้ไขการพูดมีน้อย นัดได้ห่าง
- ที่บ้านไม่มีเครื่องมือให้เด็กเห็นเสียงตัวเอง ส่วนเครื่อง Nasometer ในคลินิกราคาแพง

## วัตถุประสงค์
1. สร้างเครื่องวัดสัดส่วนเสียงจมูก (nasalance) ราคาถูกที่ใช้ที่บ้านได้
2. ทำเกมที่ใช้ค่านี้เป็นภาพป้อนกลับ ให้เด็กอยากฝึกพูดบ่อยขึ้น
3. ให้นักแก้ไขการพูดตั้งแผนและติดตามแนวโน้มการฝึกได้จากแดชบอร์ด

## หลักการทำงาน
1. แผ่นกั้นแนบใต้จมูก แยกเสียงจมูกกับเสียงปากออกจากกัน
2. ไมค์ดิจิทัล INMP441 สองตัว ตัวบนรับเสียงจมูก ตัวล่างรับเสียงปาก ต่อเข้า ESP32 ทางบัส I2S เดียวกัน
3. ESP32 กรองเสียงทั้งสองช่องด้วยย่านความถี่เดียวกัน วัดความดัง (RMS) ทุก 20–50 มิลลิวินาที แล้วคำนวณ
   `เสียงจมูก ÷ (เสียงจมูก + เสียงปาก) × 100` และตรวจว่ากำลังมีเสียงพูดไหม (`speechDetected`)
4. ส่งค่าทาง Wi-Fi (WebSocket) ไปที่เว็บเกม รูปแบบข้อมูลอยู่ใน [`docs/DEVICE_PROTOCOL.md`](docs/DEVICE_PROTOCOL.md)
5. เว็บตรวจคุณภาพสัญญาณก่อนนำไปใช้ ถ้าค่าค้าง ไมค์ช่องใดหาย เสียงแตก หรือเบาเกิน จะไม่นับ และไม่โทษเด็ก

สิ่งที่เครื่องไม่รู้: ไม่รู้ว่าเด็กพูดคำอะไร (ไม่มีการถอดเสียงเป็นคำ) มองไม่เห็นเพดานโดยตรง และไม่รู้ตำแหน่งลิ้น จึงยังต้องมีนักแก้ไขการพูดคอยฟัง

## ผู้ใช้
- **เด็ก:** เล่นเกม
- **ผู้ปกครอง:** ช่วยฝึกที่บ้าน
- **นักแก้ไขการพูด:** เลือกคำ ตั้งเกณฑ์ ดูแนวโน้มในแดชบอร์ด

## สี่เกม
| เกม | เด็กทำอะไร | เกมตอบสนองต่อ |
|---|---|---|
| เรียกเพื่อน | เรียกชื่อเพื่อน ปู หมา ปลา นก เต่า | ได้ยินเสียงพูดที่สัญญาณใช้ได้ |
| เลือกทางวิ่ง | พูดแล้วกระต่ายวิ่งทันที หนีเพื่อนเมฆที่ไล่ตาม พูดจบ 1 คำ = ถึงธง 1 ช่วง | ได้ยินเสียงพูด ความเร็วไม่ขึ้นกับค่าเสียงจมูก (เกณฑ์เสียงปากบันทึกให้ผู้ดูแลดูเท่านั้น) |
| พาบอลลูนไปส่ง | พูดต่อเนื่องให้ครบเวลาในแผน | เสียงปากถึงเกณฑ์ที่ครูตั้ง (เริ่มต้น 70%) |
| เปิดประตู | พูดคำนาสิก เช่น “มา” | เสียงจมูกถึงเป้าที่ครูตั้ง (เริ่มต้น 40%) |

ไม่มีเกมไหนใช้กติกา “ยิ่งเสียงจมูกต่ำยิ่งเก่ง” เพราะคำที่มีเสียงนาสิกต้องมีเสียงจมูกตามปกติ และเกณฑ์ทุกอันให้นักแก้ไขการพูดตั้งตามคำที่ใช้ฝึก

## หลักการบำบัดที่อ้างอิง
- วัด nasalance ด้วยแผ่นกั้นกับไมค์ 2 ตัว หลักเดียวกับ Nasometer ที่คลินิกใช้
- ภาพป้อนกลับ (biofeedback) ซึ่ง ASHA ระบุว่าเหมาะกับปัญหาที่เกิดเฉพาะบางเสียงหรือเกิดจากการเรียนรู้ผิด
- ฝึกบ่อยโดยมีคนช่วยนอกคลินิก ตามโมเดลค่ายฝึกพูดในชุมชนของมหาวิทยาลัยขอนแก่น
- ค่าปกติของเด็กไทย (Prathanee 2003) ยืนยันว่าห้ามตั้งเกณฑ์ “ยิ่งต่ำยิ่งดี”
- หลักฐานส่วนใหญ่ยังเป็นงานขนาดเล็ก สรุปงานวิจัยฉบับเต็มอยู่ใน [`evidence-th.md`](.claude/skills/cleft-speech-game/references/evidence-th.md)

ปากเก่งไม่ใช่การรักษา ไม่ใช่เครื่องวินิจฉัย และไม่ได้แทนนักแก้ไขการพูด ถ้าปัญหาอยู่ที่โครงสร้างของเพดาน ฝึกด้วยเกมก็ไม่หาย ต้องกลับไปให้ทีมเพดานโหว่ตรวจ

### เครื่องมือเดโม
อยู่ในมุม “สำหรับผู้ดูแล” ของทุกเกม (พับไว้ แตะป้าย “โหมดสาธิต” บนตลิ่งเพื่อเปิด)
- แถบเลื่อน “ค่าออกปาก (จำลอง)” 0–100% (ออกจมูก = 100 − ออกปาก)
- เสียงพูด: ไม่มีเสียง / มีเสียง / เป็นช่วง ๆ และปุ่ม “กดค้างเพื่อพูด” (หรือกด Space ค้าง)
- ตัวเลือกทดสอบเพิ่ม: ค่อย ๆ เปลี่ยน, แกว่งใกล้เกณฑ์, ตัด/ต่อการเชื่อมต่อ, **ภาพฉากเกม** (อัตโนมัติ / 3D สูง / 3D ประหยัด / 2D + ตัวนับ fps),
  **ภาพเคลื่อนไหว** (ตามเครื่อง / ลดลง / เต็ม), รีเซ็ต

### ลำดับการเล่นของแต่ละเกม (รอบปรับ 5 พ.ย.)
หน้าแรกบอกสิ่งที่แต่ละเกมชวนทำ — **เรียกเพื่อน · พาบอลลูนไปส่ง · เลือกทางวิ่ง · เปิดประตู** — แสดงเฉพาะเกมที่แผนของผู้ดูแลเปิดไว้ และมี “เล่นต่อ” จากรอบล่าสุด
- **เรียกเพื่อน** (`#/frog`): เลือกเพื่อนตัวแรก → ฟังคำ → เรียก → เพื่อนหันมา กบกระโดดไปหา → **เลือกเพื่อนตัวถัดไปเอง** → จบรอบเห็นกลุ่มเพื่อนที่ตลิ่ง
- **เลือกทางวิ่ง** (`#/runner`): เลือกทางแยกบนแผนที่ (ทางดอกไม้ → ชิงช้าสวรรค์ / ทางป่าเห็ด → บ้านเห็ด) → เริ่มพูดแล้วกระต่ายวิ่งทันที พูดจบ 1 คำ = ถึงธงจุดแวะ
  (เพื่อนเมฆไล่ตาม: เงียบแล้วเข้ามาใกล้ วิ่งแล้วทิ้งห่าง ไม่มีวันจับได้) →
  6 ช่วงถึงปลายทาง → ไปเปิดประตูต่อเมื่อแผนเปิดด่านประตู · เกณฑ์ออกปากบันทึกให้ผู้ดูแลเท่านั้น ไม่ตัดสินในฉาก
- **พาบอลลูนไปส่ง** (`#/balloon`): เลือกที่ส่ง (บ้านต้นไม้ / ประภาคาร / ปราสาทเมฆ) → ประคองเสียงตามเวลาในแผน บอลลูนลอยถึงหมุด → **พัก** (ไม่นับเสียง) → เด็กกด “ส่งลูกถัดไป”
- **เปิดประตู** (`#/gate`): เลือกบาน (ดอกไม้ / ดาว / เปลือกหอย) → ฟังคำนาสิกจากแผน → เสียงถึงเกณฑ์จมูกของผู้เชี่ยวชาญ → สลักเลื่อน ประตูเปิด เห็นสิ่งที่อยู่ข้างหลัง (เล่นเดี่ยว หรือต่อจากเกมวิ่ง)
- ทุกเกมใช้โครงเดียวกัน: ฉากเต็มจอ + “ตลิ่ง” (คำครั้งเดียว, สถานะบรรทัดเดียว, ปุ่มหลักในระยะนิ้วโป้ง) · iPad/คอมแนวนอน = ฉากคู่แถบของเกม · เครื่องมือสาธิตอยู่ในมุมผู้ดูแลที่พับไว้

### ด่านเรียกเพื่อน (กบข้ามบึง) — `#/frog`
ด่านต้นแบบที่ปรับจากกบข้ามบึงตามหลักฐานใน skill `cleft-speech-game` (`references/evidence-th.md`)
0. หน้าแรกของด่าน **“วันนี้อยากไปหาใครก่อน?”** — แตะเพื่อนบนใบบัว (ปู หมา ปลา นก เต่า ตามแผน) ตัวนั้นจะเป็นตัวแรกของรอบ
1. เด็กเห็นรูปสัตว์ กด **ฟังคำ** (หรือแตะรูป) → ได้ยินคำตัวอย่าง ระหว่างนั้นเกม **ไม่ฟังไมค์** (มีข้อความบอก)
2. ขึ้น **“ลองเรียกเพื่อนดูสิ”** → เมื่อได้ยินเสียงเรียกที่สัญญาณใช้ได้ เพื่อนหันมาและตอบ **“ได้ยินแล้ว”** แล้วกบกระโดดไปหา
   (เพื่อนหัน = ตรวจพบเสียง ไม่ได้ตัดสินว่าออกเสียงถูก)
3. ปุ่ม **ฟังซ้ำ · ลองใหม่ · ข้าม** และ **พัก** (มุมซ้ายบน) · เสียงเบา ล้น ไมค์ช่องหาย หรืออุปกรณ์หลุด → “ขอฟังอีกครั้งนะ” ไม่หักดาว ·
   จบรอบ เพื่อนที่ได้ยินมารวมกันที่ตลิ่ง แล้ว **เลือกเพื่อนแล้วเล่นอีกรอบ** หรือ **ดูสรุปรอบ**
4. **สำหรับผู้ดูแล** (ใต้ตลิ่ง หรือแตะป้าย “โหมดสาธิต”): สถานะอุปกรณ์และวิธีแก้, ตารางรายคำ (ฟังตัวอย่าง / ลองพูด / สัญญาณใช้ได้ / ออกจมูกเฉลี่ยแยกคำปากกับคำมีเสียงนาสิก), สลับแหล่งสัญญาณ
5. ป้าย **โหมดสาธิต** อยู่บนตลิ่งตลอด · ต่อ ESP32 ผ่าน WebSocket ได้ภายหลัง — รูปแบบข้อมูล `docs/DEVICE_PROTOCOL.md` ·
   เครื่องที่เปิด 3D ไม่ได้เล่นแบบ 2D ได้ครบ ถ้าเคยเลือก 2D ไว้ มีปุ่ม “ลองฉาก 3D”

ลองในเดโม: “กดค้างเพื่อพูด” (หรือ Space ค้าง) = เรียกหนึ่งครั้ง · ไม่กดอะไรเลย = ไม่มีเสียง ·
“ตัวเลือกทดสอบเพิ่ม” → ตัดการเชื่อมต่อ / ความดังเสียง (เบาเกินไป, ดังจนล้น) / ช่องไมค์หลุด / จำลองเสียงลำโพงรั่วเข้าไมค์

### ฉาก 3D
ฉากเกมทั้ง 3 เกมและด่านประตูเป็น 3D (three.js + React Three Fiber) โหลดเป็น chunk แยกเมื่อเข้าเกม;
ถ้าเบราว์เซอร์ไม่มี WebGL หรือฉาก 3D หลุด จะแสดงภาพ 2D เดิมพร้อมคำอธิบายและปุ่มลองใหม่ — เล่นและนับผลได้เหมือนเดิม
โมเดลทั้งหมดสร้างด้วยโค้ดในโปรเจกต์ (ไม่มี asset ภายนอก) — ดู `ASSETS.md`
