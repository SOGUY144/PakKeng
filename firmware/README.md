# เฟิร์มแวร์ ESP32 ของปากเก่ง

ESP32 อ่านไมค์ INMP441 สองตัว แล้วส่งค่าไปที่เว็บผ่าน WebSocket ทุก 25 ms
รูปแบบข้อความเป็นไปตาม [`docs/DEVICE_PROTOCOL.md`](../docs/DEVICE_PROTOCOL.md):

```json
{"nasalPercent":31.5,"speechDetected":true,"nasalDb":-30.2,"oralDb":-22.0,"clip":false}
```

> **สถานะ:** ต้นแบบ compile ผ่านกับ esp32 core 3.3.12 + WebSockets 2.7.2 (บอร์ด ESP32 Dev Module, ESP32S3, ESP32C3)
> **แต่ยังไม่ได้ทดสอบกับบอร์ด ไมค์ และแผ่นกั้นจริง** ค่าเกณฑ์ทุกตัวเป็นค่าตั้งต้นที่ต้องวัดใหม่
>
> เครื่องมือฝึกเสริมที่บ้าน ภายใต้คำแนะนำของนักแก้ไขการพูด
> ต้นแบบนี้ยังไม่ได้ตรวจสอบเทียบกับ Nasometer ใช้ดูแนวโน้มจากการฝึกเท่านั้น ไม่ใช้วินิจฉัย

## ไฟล์

| ไฟล์ | ทำอะไร |
|---|---|
| `pakkeng_esp32/pakkeng_esp32.ino` | ตัวหลัก: I2S, Wi-Fi, WebSocket พอร์ต 81, หน้าเช็กสถานะพอร์ต 80 และ**ส่วนตั้งค่าที่ต้องแก้** |
| `pakkeng_esp32/nasal_dsp.h` | การคำนวณ: กรองย่านความถี่, RMS, dBFS, ตรวจเสียงล้น, ตรวจเสียงพูด, สร้าง JSON (ไม่มีโค้ด Arduino) |
| `test/test_nasal_dsp.cpp` | เทสต์การคำนวณบนคอม ไม่ต้องมีบอร์ด |

## 1. ต่อสาย

### แบบสองบัส (ค่าเริ่มต้น · บอร์ดของทีมต่อแบบนี้)

ไมค์แต่ละตัวมีสาย SCK, WS, SD ของตัวเอง ESP32 อ่านผ่าน I2S สองชุด (`TWO_BUSES = 1`)

| INMP441 | ไมค์จมูก (บน) | ไมค์ปาก (ล่าง) |
|---|---|---|
| VDD | 3V3 | 3V3 |
| GND | GND | GND |
| SCK | GPIO 21 | GPIO 16 |
| WS | GPIO 19 | GPIO 17 |
| SD | GPIO 22 | GPIO 23 |
| L/R | GND หรือ 3V3 (ห้ามลอย) | GND หรือ 3V3 (ห้ามลอย) |

- เฟิร์มแวร์หาเองว่าไมค์แต่ละตัวส่งข้อมูลทางช่องซ้ายหรือขวา แล้วพิมพ์บอกใน Serial Monitor
- ถ้าเคาะไมค์บนแล้วเส้น `ไมค์2_ปาก_dB` ขยับแทน ให้ตั้ง `SWAP_CHANNELS = true`
- ขาเหล่านี้ใช้กับบอร์ดโมดูล WROOM ได้ ถ้าเป็นบอร์ด WROVER (มี PSRAM) ขา 16/17 ใช้ไม่ได้ ต้องย้ายไมค์ปากไปขาอื่น
- ESP32-C3 มี I2S ชุดเดียว ใช้ได้เฉพาะแบบบัสเดียวด้านล่าง

### แบบบัสเดียว (`TWO_BUSES = 0`)

ไมค์ทั้งสองตัวต่อขา SCK, WS และ SD **ร่วมกัน** ส่วนขา L/R ต่อต่างกัน
ด้วยวิธีนี้ไมค์ตัวหนึ่งจะอยู่ช่องซ้าย อีกตัวอยู่ช่องขวา

| INMP441 | ESP32 DevKit | ESP32-S3 | ESP32-C3 |
|---|---|---|---|
| VDD | 3V3 | 3V3 | 3V3 |
| GND | GND | GND | GND |
| SCK | GPIO 33 | GPIO 5 | GPIO 4 |
| WS | GPIO 25 | GPIO 4 | GPIO 5 |
| SD | GPIO 32 | GPIO 6 | GPIO 6 |
| **L/R ของไมค์บน (จมูก)** | **GND** → ช่องซ้าย | GND | GND |
| **L/R ของไมค์ล่าง (ปาก)** | **3V3** → ช่องขวา | 3V3 | 3V3 |

- ใช้ไฟ 3.3 V เท่านั้น ห้ามต่อ 5 V
- สาย I2S ควรสั้น (ไม่เกิน ~20 cm)
- ถ้าต่อขาอื่น ให้แก้ `PIN_I2S_SCK` / `PIN_I2S_WS` / `PIN_I2S_SD` ในส่วนตั้งค่าของไฟล์ `.ino`

## 2. ติดตั้งเครื่องมือ (ครั้งแรกครั้งเดียว)

**Arduino IDE 2**
1. ไปที่ File → Preferences → Additional boards manager URLs
   แล้วใส่ `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
2. ไปที่ Tools → Board → Boards Manager → ค้นหา **esp32 by Espressif Systems** → ติดตั้งเวอร์ชัน **3.x**
   (ทดสอบ compile กับ 3.3.12)
3. ไปที่ Tools → Manage Libraries → ค้นหา **WebSockets** → ติดตั้งตัวของ **Markus Sattler**
   (ทดสอบ compile กับ 2.7.2)
4. ถ้าเสียบบอร์ดแล้วไม่เห็นพอร์ต ให้ลงไดรเวอร์ USB ตามชิปบนบอร์ด (CP210x หรือ CH340)

**arduino-cli**

```bash
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
```

```bash
arduino-cli core update-index
```

```bash
arduino-cli core install esp32:esp32
```

```bash
arduino-cli lib install WebSockets
```

## 3. ตั้งค่าในไฟล์ `.ino` (ส่วน "ตั้งค่า" ด้านบน)

- **ใช้ Wi-Fi ของบอร์ดเอง** (ค่าเริ่มต้น): ปล่อย `WIFI_SSID` ว่างไว้
  - บอร์ดจะเปิด Wi-Fi ชื่อ `PakKeng-XXXX` รหัส `pakkeng123`
  - ที่อยู่สำหรับใส่ในเว็บคือ `ws://192.168.4.1:81`
- **ใช้ Wi-Fi บ้าน**: ใส่ `WIFI_SSID` และ `WIFI_PASSWORD`
  - เลข IP ของบอร์ดจะขึ้นใน Serial Monitor
  - ถ้าต่อ Wi-Fi บ้านไม่ได้ภายใน 15 วินาที บอร์ดจะเปิด Wi-Fi ของตัวเองแทน
- **เปลี่ยนรหัส `AP_PASSWORD`** ก่อนใช้จริง (อย่างน้อย 8 ตัว ถ้าสั้นกว่านี้บอร์ดจะเปิด Wi-Fi ไม่ได้)
- **ไฟบอกเสียงพูด:** ใช้ไฟบนบอร์ดเป็นค่าเริ่มต้น
  - ถ้าไฟติดค้างหรือกลับด้าน (เช่น ESP32-C3 SuperMini) ให้ตั้ง `LED_ACTIVE_LOW = true`
  - ไม่ต้องการไฟ ให้ตั้ง `LED_PIN = -1`

## 4. อัปโหลด

**Arduino IDE**
1. เปิดไฟล์ `firmware/pakkeng_esp32/pakkeng_esp32.ino`
2. Tools → Board: เลือก **ESP32 Dev Module** (หรือ ESP32S3 Dev Module / ESP32C3 Dev Module ตามบอร์ด)
3. **บอร์ด S3/C3 ที่เสียบสายเข้าพอร์ต USB ของชิปโดยตรง** (เช่น C3 SuperMini): ตั้ง Tools → **USB CDC On Boot: Enabled**
   ไม่อย่างนั้น Serial Monitor และ Serial Plotter จะไม่ขึ้นอะไรเลย
4. Tools → Port: เลือกพอร์ตของบอร์ด
5. กด Upload
   - ถ้าค้างที่ `Connecting....` ให้กดปุ่ม **BOOT** บนบอร์ดค้างไว้จนเริ่มเขียน
6. เปิด Serial Monitor ที่ **115200** แล้วกดปุ่ม **EN/RST** บนบอร์ดหนึ่งครั้ง
   (หรือพิมพ์อะไรก็ได้แล้วกด Enter) จะเห็นที่อยู่ WebSocket, ชื่อ Wi-Fi และหน้าเช็กสถานะ

**arduino-cli** (แทน `COM5` ด้วยพอร์ตจริงจาก `arduino-cli board list`)
- รหัสบอร์ด: ESP32 DevKit = `esp32:esp32:esp32` · S3 = `esp32:esp32:esp32s3` · C3 = `esp32:esp32:esp32c3`
- บอร์ด S3/C3 ที่ใช้ USB ของชิปโดยตรง ให้ต่อท้ายรหัสบอร์ดด้วย `:CDCOnBoot=cdc`

```bash
arduino-cli compile --fqbn esp32:esp32:esp32 firmware/pakkeng_esp32
```

```bash
arduino-cli upload --fqbn esp32:esp32:esp32 -p COM5 firmware/pakkeng_esp32
```

```bash
arduino-cli monitor -p COM5 -c baudrate=115200
```

## 5. ต่อกับเว็บ

1. ให้มือถือหรือคอมที่เปิดเว็บอยู่วง Wi-Fi เดียวกับบอร์ด
   - **ใช้ Wi-Fi บ้าน:** บนคอมรัน `npm run dev -- --host` แล้วเปิด `http://<IP ของคอม>:5173` จากมือถือ
   - **ใช้ Wi-Fi ของบอร์ด:** ให้ทั้งคอมและมือถือเข้า Wi-Fi `PakKeng-XXXX`
     - บนคอมรัน `npm run dev -- --host` แล้วเปิด `http://<IP ของคอมในวงนั้น>:5173`
     - **Android:** Wi-Fi นี้ไม่มีอินเทอร์เน็ต มือถืออาจถามว่าจะใช้ต่อไหม ให้กด "ใช้ต่อ" และปิดเน็ตมือถือระหว่างใช้
       ไม่อย่างนั้นมือถืออาจส่งข้อมูลผ่านเน็ตมือถือจนต่อบอร์ดไม่ได้
2. เข้าเกมไหนก็ได้ → เปิด **สำหรับผู้ดูแล** → **แหล่งสัญญาณ**
   - ใส่ที่อยู่ เช่น `ws://192.168.4.1:81`
   - กด **อุปกรณ์ ESP32**
3. ถ้าบอร์ดรีเซ็ตหรือ Wi-Fi หลุด เว็บจะต่อใหม่เอง (รอ 1, 2, 4 แล้วทุก 5 วินาที)
   - ระหว่างรอจะขึ้นว่า "หลุด" และไม่นับรอบนั้นเป็นความผิดของเด็ก
   - ถ้าใช้ Wi-Fi ของบอร์ด หลังบอร์ดรีเซ็ตมือถืออาจย้ายไปต่อ Wi-Fi อื่น ให้เช็กว่ามือถือกลับมาอยู่ที่ `PakKeng-XXXX`

**ข้อจำกัด**
- เว็บที่เปิดผ่าน https (เช่น Vercel) ต่อ `ws://` ไม่ได้ ต้องเปิดเว็บผ่าน http ในวงเดียวกัน
- บอร์ดรับเว็บที่ต่อพร้อมกันได้ราว 5 เครื่อง
- ถ้ามือถือที่ต่ออยู่ล็อกจอโดยไม่ปิดหน้าเว็บ บอร์ดอาจส่งค่าสะดุดไม่กี่วินาทีจนตัดมือถือเครื่องนั้นออก
  ระหว่างนั้นเว็บเครื่องอื่นจะเห็นเป็น "ข้อมูลค้าง" และไม่นับคะแนน

## 6. ตรวจก่อนใช้ (สำคัญ)

1. **หน้าเช็กสถานะ:** เปิด `http://192.168.4.1/` (หรือ IP ของบอร์ด) จากมือถือ
   - หน้านี้แสดงระดับเสียงสองไมค์ มีเสียงพูดไหม และจำนวนเว็บที่ต่ออยู่
   - รีเฟรชเองทุกวินาที
2. **เคาะไมค์ทีละตัว** แล้วดูใน Tools → Serial Plotter
   - เคาะไมค์บน แล้วเส้น `ไมค์1_จมูก_dB` ต้องขยับ
   - ถ้าเส้น `ไมค์2_ปาก_dB` ขยับแทน ให้ตั้ง `SWAP_CHANNELS = true` หรือสลับขา L/R
3. **ช่องไหนขึ้น "ไม่มีสัญญาณ"** ให้ตรวจสาย SD, ขา L/R และไฟ 3V3 ของไมค์ตัวนั้น
   - หลังเปิดเครื่องราวหนึ่งในสี่วินาที ไมค์ยังไม่ส่งเสียง จึงอาจเห็น "ไม่มีสัญญาณ" แวบหนึ่งได้ เป็นเรื่องปกติ
4. **ไฟบนบอร์ด (ถ้ามี)** ติดเมื่อบอร์ดได้ยินเสียงพูด
5. วัดระดับเงียบและระดับพูดจริงกับแผ่นกั้น แล้วปรับเกณฑ์ตาม `TODO.md` และ `docs/DEVICE_PROTOCOL.md`

## การคำนวณ (สรุป)

- **ความถี่:** 16 kHz ช่องละ 24 บิต หน้าต่างละ 25 ms (400 ตัวอย่าง)
- **nasalPercent:** = 100 × A_จมูก / (A_จมูก + A_ปาก)
  - A คือ RMS หลังผ่านตัวกรองย่านความถี่ตัวเดียวกัน (ศูนย์กลาง 500 Hz กว้าง 300 Hz แบบ Nasometer)
- **nasalDb / oralDb:** ระดับทั้งย่านความถี่หลังตัด DC เป็น dBFS
  - ช่องที่ได้ 0 ล้วนทั้งหน้าต่าง (ไมค์หลุด) ส่ง `null`
  - เปิด pull-down ที่ขา SD ไว้ ไมค์ที่หลุดจึงอ่านได้ 0 ไม่ใช่ค่าขยะ
- **clip:** มีตัวอย่างใดถึง 99.9% ของ full scale
- **speechDetected:** ระดับในย่านกรองสูงกว่าระดับเสียงรบกวนที่บอร์ดเรียนรู้เอง
  - เริ่มนับเมื่อสูงกว่า +10 dB และยังนับต่อเมื่อสูงกว่า +6 dB
  - ต้องไม่ต่ำกว่า −75 dBFS
  - มี hangover 150 ms
  - ครึ่งวินาทีแรกหลังเปิดเครื่องใช้เรียนรู้ห้อง
  - หน้าต่างที่ได้ 0 ล้วนหรือไมค์หายตัวใดตัวหนึ่ง ไม่นับเป็นเสียงพูดและไม่ใช้เรียนรู้ห้อง
  - เสียงดังต่อเนื่องเกิน 8 วินาที (เช่น เปิดพัดลม) จะถูกเรียนรู้เป็นเสียงรบกวนภายในราว 10 วินาที
